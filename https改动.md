  使用方式

  开发环境（本机调试）：
  dotnet dev-certs https --trust   # 首次运行，信任开发证书
  dotnet run --launch-profile https
  之后 https://localhost:3001 可访问，http://localhost:3000 的请求会自动 307 重定向到 HTTPS。

  生产环境（正式证书）：
  1. 把证书（pfx 格式）放到服务器，比如 /etc/certs/hanjiannet.pfx
  2. 在 appsettings.json 配置：
  "Https": {
    "Port": 3001,
    "Certificate": {
      "Path": "/etc/certs/hanjiannet.pfx",
      "Password": "证书密码"
    }
  }
  3. 没配证书时服务照常启动，只监听 HTTP 并在日志里警告——不会像以前配置那样直接启动失败。

  两点提醒

  - 证书格式：UseHttps(path, password) 用的是 pfx（含私钥）。如果你拿到的是 nginx 常用的 crt + key 对，需要先转换：openssl pkcs12 -export -out cert.pfx -inkey cert.key -in cert.crt
  - 如果站点前面有 nginx 反代：更常见的做法是 HTTPS 终结在 nginx 层（证书配在 nginx），Kestrel 只跑 HTTP。这套配置依然兼容——只需不加 Https:Certificate，同时把 UseHttpsRedirection/UseHsts 交给
    nginx 处理即可（当前代码在没启用 HTTPS 端口时不会加重定向，正好不会冲突）。
